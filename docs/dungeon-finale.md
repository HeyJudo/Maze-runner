# Level 4: Forgotten Keep

The finale is a 47-column by 37-row dungeon with two seal wings and a mechanical
gauntlet guarding the exit. It uses the same controls, hearts, menus, score panels,
marble material, and shared Full / 1.5x / 2x camera as the earlier levels.

## Playing the level

Leave the southern entrance and choose either maze wing. Find the ember and
amethyst seals; each opens its matching barred shortcut back toward the central
hall. Both seals unlock the final exit gate. Loops, dead ends, optional healing
detours, barred cells, altars, broken stonework, and torches distinguish the wings.
Holding Tab gives the full overview while using a closer camera.

The last approach combines a moving saw chamber, a projectile crossing, a
mandatory spike bridge, and a final horizontal blade. This is a mechanical
boss-style encounter: observe a cycle, brake in a safe area, and commit to the
crossing. There is no enemy boss or forced countdown. The star par is 60 seconds;
exploration and recovery can take as long as the player needs.

| Hazard | Behavior | Opportunity |
| --- | --- | --- |
| Spikes | Six-second cycle; amber warning from 1.3–2.0 seconds, active from 2.0–3.2 seconds | Wait off the marked tiles until the spikes retract |
| Ground blades | Spin while moving horizontally or vertically along visible rails; six-second period with 0.6-second endpoint dwell | Watch their position and cross behind them |
| Wall darts | Amber launcher and dotted firing lane warn for 0.8 seconds; three shots 0.25 seconds apart | Shelter behind stone walls and cross after the shots pass |

Trap hits cost one heart and use the existing one-second damage protection.
Wall contacts still cost a quarter heart. A pit costs one heart and returns the
marble to the entrance while keeping collected seals and opened gates. Restart
begins a fresh attempt with three hearts, closed gates, and reset traps/pickups.
Pause, focus loss, and camera changes while paused freeze the trap clock too.

The HUD shows seal progress and the exit's locked/open status. Campaign victory
now follows Level 4. Full-run records carry the number of campaign levels, so
older three-level times remain saved without competing with four-level times.

## Artwork

Purple masonry, cracked slate floors, warm torchlight, iron gates, seal altars,
and trap artwork are drawn by `DungeonRenderer`. The silver marble picks up a
warm dungeon reflection. Stonework is cached with the existing renderer; trap
states and landmarks are drawn from the live dungeon runtime.

These are custom procedural graphics. The suggested Raou pack at
<https://raou.itch.io/free-dungeon-mini-tileset> was **not imported**: its download
page was blocked by the cloud environment's network policy. Domain additions
for `raou.itch.io` and `img.itch.zone` were saved in the environment configuration
draft for review. Original pack files and their license must be retrieved before
replacing this artwork with those tiles. The two new WAV cues are generated by
`python3 tools/gen_dungeon_sounds.py` and do not use external samples.

## Level authoring

`GravityMaze/Mazes/Level4.txt` contains the collision grid;
`Level4.dungeon.json` contains spike positions/phases, saw tracks, launcher
positions/directions/phases, and decorative landmarks. Coordinates are zero-based
tile units. `MazeManager` automatically loads a matching `.dungeon.json` sidecar.

| New tile | Meaning |
| --- | --- |
| `K` / `Q` | Ember / amethyst seal |
| `a` / `b` | Gate opened by the matching seal |
| `E` | Exit gate requiring both seals |
| `T` | Spike tile, requiring a unique sidecar spike entry |

Dungeon data validates before play. Blade tracks must be cardinal, stay on
floor, and have periods of at least four seconds. Dart launchers require cardinal
directions. The engine owns objective state, clocks, projectiles, swept hazard
collisions, and damage. Rendering reads this state without driving gameplay.

## Validation

With .NET 10, from the repository root:

```sh
dotnet run --project tools/DungeonChecks/DungeonChecks.vbproj -c Release
dotnet run --project tools/TransitionChecks/TransitionChecks.vbproj -c Release
dotnet run --project tools/CameraChecks/CameraChecks.vbproj -c Release
dotnet run --project tools/HealthChecks/HealthChecks.vbproj -c Release
dotnet run --project tools/MarbleChecks/MarbleChecks.vbproj -c Release
dotnet run --project tools/PerspectiveChecks/PerspectiveChecks.vbproj -c Release
```

Dungeon checks cover seal collection, gate collision, the locked goal, warning and
active boundaries, moving saw/projectile collision between frames, bursts,
contact suppression, health protection, retry/pit behavior, and legacy record
loading. Four full runs use actual -1/0/+1 tilt inputs with health and all traps
enabled, at different initial trap phases. No marble position changes or health
disabling are used in those proof runs. The real-shell checks also complete a
four-level campaign and verify paused trap clocks, cue wiring, and record scope.

Cloud validation passed 5,269 checks: dungeon 535, shell/transition 376, camera
859, health 98, marble 1,014, and perspective 2,387. The four dungeon clears took
48.32–49.79 seconds with 2–3 hearts remaining, one hit per run, and actual waiting
for trap windows. Release cross-builds of the game and verification runner passed
with zero warnings and errors.

On Windows, run the rendering tours:

```sh
dotnet run --project tools/VerificationRunner/VerificationRunner.vbproj -- --dungeon-only
dotnet run --project tools/VerificationRunner/VerificationRunner.vbproj -- --camera-only
dotnet run --project tools/VerificationRunner/VerificationRunner.vbproj -- --ui-only
```

The dungeon tour saves 48 presentation fixtures covering trap/seal states,
three camera settings, two sizes, and flat/perspective views. The UI tour captures
the four-level campaign, dungeon HUD, four-card selector, and five-column records.
These desktop tours require Windows and were not run in the Linux environment.
The game and runner can be cross-built there with `-p:EnableWindowsTargeting=true`.

Before merging, play with keyboard and the Arduino board. Check warning
visibility at every zoom, projectile lanes and saw silhouettes, safe waiting
areas, gate opening, the final spike crossing, resizing/fullscreen, and dungeon
landing/victory. Automated clears establish a workable route; human playtesting
is still needed to judge exploration difficulty and control comfort.
